# Architect-Implementer

## Record-Only Maintenance

For organizing existing multi-document plan/handoff records, read only "Artifact Organization" in [checkpoint.md](references/checkpoint.md). Preserve role ownership and active entrypoints; do not dispatch or resume workers for this operation. This is not general project documentation management. Otherwise choose the current operation below.

## Ownership

Selected Astra keeps architecture, requirements, plan/design documents and their review/editing regardless of length, bounded edits and independent acceptance. Sustained implementation/repair/debugging/integration or cross-file contracts needing an implementer go to independent Sol High. Judge impact, not line count; preserve existing edits when handing off. Astra may revise design and run focused acceptance probes, not repair delegated product code or enter implementation loops.

Direct Sol owns its task; direct Luna stays local. Workers never start another Astra. Apply [shared boundaries](references/boundaries.md) when this workflow is used; no personal global AGENTS file is required.

## Planning Context

Sol handles sustained implementation. [Luna](../sol-luna-mechanical/SKILL.md) is available when the user or coordinating Astra/Sol explicitly selects fixed-rule mechanical work of any volume needing little judgment. [DeepSeek](../independent-review/SKILL.md) provides independent read-only review, coordinated by Sol; the existing owner accepts.

Agent implementation planning uses these roles and relevant workflow support. Reading guidance does not start execution; plan-only requests stop without implementation. Scheduled external review identifies when and which candidate files/directories to review, not how to review them.

## Read for the Current Operation

For stage review or final verification, read the effective contract, actual candidate, cumulative changes, evidence, open work and any Luna/DeepSeek results used. Do not default to rereading every role or runtime procedure. Stage review and final verification may share a turn. Do not reload unchanged support/history within a continuous turn.

- [recovery.md](references/recovery.md): actual interruptions, missing tools, uncertain creation or replacement.

Resolve bundled references from this installed Skill's path, not a remembered source/cache version. Task records remain outside the package.

Save the effective contract before actual dispatch.

## Astra: Review and Final Verification

Independently check the actual candidate against important contracts/invariants and credible evidence under verified identity/assignment. Worker "done" or DeepSeek approval is not acceptance. Disposable acceptance outputs are allowed; product source/configuration fixes return to Sol. Do not replay accepted unchanged scope or broad suites without reason.

Consolidate known findings into concrete rework for the same Sol; record actual delivery. Return PASS, REWORK or BLOCKED. Only overall PASS with all required work/checks/processes resolved permits final outcome/completed timestamp. Stage acceptance is not overall completion. New important defects may require further checks; external-review budgets do not cap Astra acceptance.

## Sol: Implement and Deliver

Own implementation, ordinary debugging/integration, tests and evidence under the effective contract, preserving unrelated edits. Apply verified contract changes in the same healthy chat; use communication support for escalation and cumulative delivery. At configured review points resolve ordinary findings under the review policy, retaining unavailable/unverified review and open checks. Runtime recovery stays local under recovery support.
